# משימות למפתח — מרכז העזרה וסרטוני ההדרכה

הקוד כבר ב-`main`. נשארו שלושה דברים שדורשים גישה לחשבונות (Vercel / Google Cloud / Anthropic),
ולכן אי אפשר לבצע אותם מתוך סביבת הפיתוח. סדר מומלץ: 1 → 2 → 3.

---

## 1. הפעלת העוזר החכם במרכז העזרה (10 דקות)

**מה זה:** במסך `/dashboard/help` המשתמש כותב שאלה חופשית. היום, בלי מפתח, המערכת מחפשת את
התשובה הקרובה מתוך 185 שאלות נפוצות. עם מפתח של Anthropic, העוזר עונה בשיחה חופשית מתוך המדריך המלא.
כל משתמש מקבל רק את המדריך של מה שהוא רואה: בעלים או מזכירה מקבלים הכל, ומשכיר מקבל השכרות בלבד.
הקוד נמצא ב-`apps/web/lib/help/assistant.ts`.

**לבצע:**
1. ב-https://console.anthropic.com יוצרים API Key, ומגדירים תקרת הוצאה חודשית ב-Billing → Limits.
2. ב-Vercel → הפרויקט `ultranet-platform` → Settings → Environment Variables:
   מוסיפים `ANTHROPIC_API_KEY` = המפתח, עבור Production (ואם רוצים, גם Preview).
3. **Redeploy** לפריסה האחרונה. Vercel לא טוען משתנה חדש לפריסה שכבר רצה.

**בדיקה:** נכנסים ל"עזרה ושאלות" ושואלים, למשל: "הלקוח החזיר מחשב ולא שילם, מה עושים?".
אמורה להגיע תשובה מנוסחת, ולא העתק של שאלה נפוצה. אם משהו נכשל, המערכת חוזרת לבד למצב
השאלות הנפוצות, והשגיאה נרשמת בלוג של Vercel עם הקידומת `[help]`.

**עלות (הערכה):** כל שאלה שולחת את המדריך המלא (כ-50 אלף טוקנים) והוא נשמר במטמון ל-5 דקות.
שאלה ראשונה אחרי הפסקה ≈ 25 סנט, שאלות נוספות באותן 5 דקות ≈ 1–2 סנט. לאמת מול Usage בקונסולה אחרי כמה ימים.

## 2. קריינות קולית לשני סרטוני ההדרכה (כשעה)

**מה זה:** `apps/web/public/help-videos/owner.mp4` ו-`renter.mp4` מוכנים, עם תמונה ב-1080p וכתוביות בעברית,
אבל **בלי קול**. הקריינות נוצרת אוטומטית דרך Google Cloud Text-to-Speech בקול גברי.
כל הכלים נמצאים ב-`tools/tutorial-videos` (ראו ה-README שם).

**א. מפתח Google:**
1. ב-Google Cloud Console יוצרים פרויקט (או משתמשים בקיים), ומפעילים את **Cloud Text-to-Speech API**.
2. ב-APIs & Services → Credentials → Create API key. מגבילים את המפתח ל-Text-to-Speech בלבד.
3. יש מכסה חינמית חודשית. כל הקריינות בשני הסרטונים היא בערך 12 אלף תווים, כך שבפועל לא אמור להיות חיוב.

**ב. הרצה** (דורש Node 20+, Java, ffmpeg, Chromium/Playwright):
```bash
# טרמינל 1 — מסד נתוני הדגמה מקומי (Firestore Emulator)
npx firebase-tools emulators:start --only firestore --project ultranet-e94aa

# טרמינל 2 — האפליקציה מול ה-Emulator. ב-apps/web/.env.local:
#   FIRESTORE_EMULATOR_HOST=127.0.0.1:8080
#   NEXTAUTH_SECRET=demo-secret-for-local-recording
#   NEXTAUTH_URL=http://localhost:3001
#   FIREBASE_PROJECT_ID=ultranet-e94aa
#   FIREBASE_CLIENT_EMAIL=demo@ultranet-e94aa.iam.gserviceaccount.com
#   FIREBASE_PRIVATE_KEY="<מפתח RSA פיקטיבי: openssl genrsa 2048, בשורה אחת עם \n>"
cd apps/web && npx next build && npx next start -p 3001

# טרמינל 3 — הקלטה + קול + הרכבה (כ-15 דקות לכל סרטון)
cd tools/tutorial-videos && npm install
export GOOGLE_TTS_API_KEY=<המפתח>
npm run record:renter && npm run tts:renter && npm run build:renter
npm run record:owner  && npm run tts:owner  && npm run build:owner
cp out/renter.mp4 out/owner.mp4 ../../apps/web/public/help-videos/
```

⚠️ **חשוב:** `.env.local` חייב להצביע על ה-Emulator. סקריפט נתוני ההדגמה (`seed.cjs`) **מוחק** את מסד
הנתונים שהוא מחובר אליו, ולכן הוא מסרב לרוץ מול כל כתובת שאינה מקומית. אסור להריץ את ההקלטה מול
Firestore האמיתי.

**בדיקה:** לצפות בשני הסרטונים. הקול, הכתוביות והפעולות על המסך צריכים להיות מסונכרנים: כל קטע מתארך
לבד לפי אורך הקול. אחר כך עושים Commit ו-Push ל-`main`.

**בעתיד:** כשמסך משתנה, מעדכנים את הקטע המתאים ב-`renter.cjs` או ב-`owner.cjs` (טקסט + פעולות) ומריצים שוב.

## 3. אחרי הפריסה — בדיקה של שלושת התיקונים (10 דקות)

| תיקון | איך בודקים |
|---|---|
| בכפתור הכניסה עם Google היה כתוב רק "התחברות עם" | עמוד הכניסה מציג "התחברות עם Google" |
| הקוביות "הכנסות/הוצאות עד היום" בדף הבית ספרו רק שורות מהיום, וכמעט תמיד הראו 0 | המספרים בדף הבית זהים ל"הכנסנו/הוצאנו עד היום" במסך הנה"ח → ראשי |
| הכפתור "בדוק הרשאות השכרות לכל הסניפים" דרס תפקידים, וגם יכול היה להוריד את הבעלים לשותף | ההודעה אחרי לחיצה כוללת עכשיו כמה סניפים דולגו כי המייל שלהם שייך לבעלים. בעלים לא משתנה לעולם; למשתמש קיים *נוסף* תפקיד במקום להחליף את הקיים |

**לבדוק פעם אחת בנתונים הקיימים:** אם הכפתור הישן הורץ בעבר, ייתכן שמשתמש כבר נפגע. ב-Firestore,
בקולקשן `n_users`:
- לוודא שלמשתמש של בעל העסק יש `role: "owner"` ו-`branchId: "all"`.
- לבדוק שותפים שאמורים להיות בכמה סניפים, או שהם גם עובדים בחדר מחשבים. אם התפקיד שלהם השתנה,
  מתקנים במסך "משתמשים" → "עריכה" → "הוספת תפקיד נוסף".
