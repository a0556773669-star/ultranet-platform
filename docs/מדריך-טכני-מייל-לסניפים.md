# מדריך טכני: הפעלת שליחת הדו"ח החודשי במייל לסניפים

> **למי המסמך:** לאדם טכני שעוזר לבעל העסק להפעיל את שליחת המיילים במערכת אולטרנט.
> לא צריך לכתוב קוד: הקוד כבר קיים ופרוס. חסרה **הגדרה של שירות המייל ושל הדומיין**.
> זמן משוער: 30–60 דקות, רובו המתנה לאימות DNS.

---

## 0. תקציר למי שממהר

1. לפתוח חשבון ב-**Resend** (resend.com), וליצור **API Key**.
2. לאמת ב-Resend **דומיין** של העסק (להוסיף רשומות DNS מסוג SPF/DKIM אצל ספק הדומיין).
3. להגדיר בפריסה (Vercel) שלושה משתני סביבה:
   `RESEND_API_KEY`, `REPORT_FROM_EMAIL`, `CRON_SECRET`.
4. **Redeploy**.
5. לבדוק במערכת: הנה"ח ← ניידים ← "שלח מייל לבדיקה" אל המייל שלך, ואז "שלח לסניפים נבחרים"
   לסניף אחד.

למה זה לא עובד היום: בלי `RESEND_API_KEY` המערכת לא שולחת בכלל. בלי דומיין מאומת + `REPORT_FROM_EMAIL`
היא שולחת מכתובת הבדיקה של Resend (`onboarding@resend.dev`), ו-Resend **חוסם כל שליחה מכתובת הבדיקה
לכל כתובת חוץ מזו שאיתה נפתח החשבון**. לכן "שלח לכל הסניפים" נכשל אצל כל השותפים.

במסך (`/dashboard/accounting/mobile`, בעלים בלבד) יש ארבעה כפתורים:
**תצוגה מקדימה** (עובד תמיד, בלי מייל), **שלח מייל לבדיקה** (לכתובת לבחירה, לא מסמן "נשלח"),

"מצב בדיקה" כשאין `REPORT_FROM_EMAIL`. אלה ההודעות מ-`mailerConfigError()` / `SANDBOX_NOTICE`
ב-`lib/mailer.ts`.

## 2. Resend — חשבון ומפתח

1. להירשם ב-https://resend.com. מומלץ להירשם עם המייל של בעל העסק (`a0556773669@gmail.com`),
   כדי שעוד לפני אימות הדומיין אפשר יהיה לשלוח לו מייל בדיקה.
2. **API Keys → Create API Key**.
   - Name: `ultranet-production`
   - Permission: **Sending access** מספיק (לא צריך Full access).
   - Domain: אפשר להשאיר All domains, או להגביל לדומיין שתאמת בשלב 3.
3. להעתיק את המפתח (מתחיל ב-`re_`). **הוא מוצג פעם אחת בלבד.** לא לשלוח אותו בצ'אט/מייל גלוי;
   להדביק ישר ב-Vercel.

מגבלות החבילה החינמית של Resend (נכון לכתיבה): 100 מיילים ביום, 3,000 בחודש, דומיין אחד. לכמה
עשרות סניפים בחודש זה מספיק בהרבה.

## 3. אימות דומיין (החלק שבאמת חסר)

בלי זה אי אפשר לשלוח לשותפים. צריך דומיין שבשליטת העסק (למשל `ultranet.co.il`).
**אסור להשתמש ב-`gmail.com`** — אי אפשר לאמת דומיין שאינו שלך.

1. Resend → **Domains → Add Domain**.
   - מומלץ תת-דומיין ייעודי, למשל `mail.ultranet.co.il` או `reports.ultranet.co.il`, כדי לא לגעת
     ברשומות המייל הקיימות של הדומיין הראשי.
   - Region: אפשר להשאיר ברירת מחדל (או `eu-west-1`, קרוב יותר לישראל).
2. Resend יציג רשימת רשומות DNS. בדרך כלל:
   - **MX** על `send.<תת-דומיין>` (ל-bounce/return-path)
   - **TXT** (SPF) על `send.<תת-דומיין>`: `v=spf1 include:amazonses.com ~all`
   - **TXT** (DKIM) על `resend._domainkey.<תת-דומיין>`: מפתח ארוך שמתחיל ב-`p=`
   - מומלץ גם **TXT** (DMARC) על `_dmarc.<הדומיין>`: `v=DMARC1; p=none;` (אם אין כבר DMARC)
   **להעתיק את הערכים בדיוק ממסך Resend** — הערכים למעלה הם דוגמה למבנה בלבד.
3. להוסיף את הרשומות אצל ספק ה-DNS של הדומיין (Cloudflare / GoDaddy / Box / דומיין ישראלי וכו').
   - ב-Cloudflare: רשומות מייל חייבות להיות **DNS only** (ענן אפור), לא Proxied.
   - יש ספקים שמוסיפים את שם הדומיין אוטומטית לשדה Name — אז מזינים רק `send.mail` ולא
     `send.mail.ultranet.co.il` (אחרת יוצא כפול).
4. ב-Resend ללחוץ **Verify DNS Records**. זה לוקח בין דקות לכמה שעות. אפשר לבדוק מבחוץ:
   ```bash
   dig TXT resend._domainkey.mail.ultranet.co.il +short
   dig TXT send.mail.ultranet.co.il +short
   ```
5. כשהסטטוס **Verified** — ממשיכים.

## 4. משתני סביבה ב-Vercel

Vercel → הפרויקט של `apps/web` (שם הפרויקט ב-Vercel כנראה `ultranet-platform`) →
**Settings → Environment Variables**. להוסיף ל-**Production** (ורצוי גם Preview):

| Key | Value | הערות |
|---|---|---|
| `RESEND_API_KEY` | `re_...` | מהשלב 2 |
| `REPORT_FROM_EMAIL` | `אולטרנט <reports@mail.ultranet.co.il>` | **חייב** להיות על הדומיין שאומת בשלב 3. הפורמט `שם <כתובת>` תקין; שם בעברית עובד |
| `CRON_SECRET` | מחרוזת אקראית ארוכה (למשל `openssl rand -hex 32`) | לשליחה האוטומטית ב-1 לחודש. Vercel Cron שולח אותו לבד כ-`Authorization: Bearer ...` |

(`REPORTS_CRON_SECRET` הוא שם חלופי שהקוד מקבל גם הוא — מספיק אחד מהשניים.)

**אחרי השמירה חובה Redeploy:** Deployments → הפריסה האחרונה של Production → `⋯` → **Redeploy**.
Vercel לא מזריק משתנים חדשים לפריסה שכבר רצה.

אם האפליקציה **לא** על Vercel (שרת אחר / Docker) — אותם שלושה משתנים בקובץ הסביבה של השרת
(`apps/web/.env.local` או משתני הסביבה של הקונטיינר), ואז restart. במקרה כזה ה-cron של
`vercel.json` לא רץ, וצריך cron חיצוני שקורא ל:
```bash
curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://<הדומיין-של-האפליקציה>/api/rentals/monthly-reports
```
ב-1 לכל חודש (למשל 09:00 שעון ישראל). ברירת המחדל היא החודש **שנסגר**; אפשר לכפות חודש עם
`?month=2026-09`.

## 5. כתובות המייל של הסניפים

לכל סניף שיש בו שותף צריכה להיות כתובת, אחרת הוא יסומן "אין כתובת מייל מוגדרת לסניף":

- **עדיף:** השכרות ← סניפים ← עריכת הסניף ← שדה **מייל השותף** (`partnerEmail`).
- אחרת: משתמש במערכת (`/dashboard/users`) שה"סניף" שלו הוא הסניף הזה — ייקח את המייל שלו.

סניפים שהם "שלי" (`isMine`, בלי שותף) **לא מקבלים דו"ח בכוונה** — אין מול מי להתחשבן.
גם סניף שסומן "עדיין לא התחיל לפעול" או נמחק לא מקבל.

## 6. בדיקה מקצה לקצה

1. להתחבר כבעלים → **הנה"ח ← ניידים** (`/dashboard/accounting/mobile`).
2. **תצוגה מקדימה** — לוודא שהדו"ח נראה נכון (מספרים, שם שותף, לוגו).
3. **שלח מייל לבדיקה** → "לאיזה מייל" = המייל שלך, "של איזה סניף" = סניף כלשהו → **שלח**.
   צריך להגיע תוך דקה, עם כותרת `[בדיקה] ...`. בדיקה **לא** מסמנת "נשלח".
4. לבדוק ב-Gmail: **Show original** → `SPF: PASS`, `DKIM: PASS`. אם לא — חזרה לשלב 3.
5. **שלח לסניפים נבחרים** → לסמן **סניף אחד בלבד** (רצוי של מישהו שאפשר לשאול אם הגיע) → שלח.
   בחלון התוצאה כל סניף מקבל ✓ ירוק או הודעת שגיאה מלאה מ-Resend.
6. רק אחרי זה — **שלח לכל הסניפים** או בחירה רחבה.

בדיקת ה-cron בלי לחכות ל-1 לחודש (זה **שולח באמת** לכל מי שעוד לא קיבל את החודש הזה):
```bash
curl -i -H "Authorization: Bearer <CRON_SECRET>" "https://<הדומיין>/api/rentals/monthly-reports?month=2026-09"
```
תשובה תקינה: JSON עם `sent`, `skipped`, `failed`. `503` = חסר משתנה סביבה. `401` = סוד שגוי.
ב-Vercel: **Settings → Cron Jobs** מראה את ה-job ואת הריצות שלו.

## 7. תקלות נפוצות

| מה רואים | הסיבה | מה עושים |
|---|---|---|
| "שליחת המייל לא מוגדרת עדיין: חסר RESEND_API_KEY" | המשתנה לא מוגדר בפריסה, או שלא נעשה Redeploy | סעיף 4, ואז Redeploy |
| הערה "מצב בדיקה" / "שליחה לסניפים תיכשל כרגע" | אין `REPORT_FROM_EMAIL` | סעיפים 3–4 |
| שגיאת Resend: `You can only send testing emails to your own email address` | שולחים מ-`onboarding@resend.dev` לכתובת זרה | לאמת דומיין ולהגדיר `REPORT_FROM_EMAIL` |
| שגיאת Resend: `The <domain> domain is not verified` | `REPORT_FROM_EMAIL` על דומיין שלא אומת (או תת-דומיין אחר מזה שאומת) | הכתובת חייבת להיות בדיוק על הדומיין שב-Resend מופיע כ-Verified |
| שגיאת Resend: `API key is invalid` / 401 | מפתח שגוי / נמחק / רווח מיותר בהדבקה | ליצור מפתח חדש ולהחליף |
| `Too many requests` / 429 | יותר מ-2 בקשות בשנייה | נדיר (השליחה סדרתית). להריץ שוב — מי שכבר קיבל ידולג |
| המייל מגיע לספאם | אין DMARC, או דומיין חדש | להוסיף DMARC, לבקש מהשותפים לסמן "לא ספאם" בפעם הראשונה |
| "אין כתובת מייל מוגדרת לסניף" | לסניף אין `partnerEmail` ואין משתמש משויך | סעיף 5 |
| "כבר נשלח לחודש הזה - דולג" | "שלח לכל הסניפים" לא שולח פעמיים | לשליחה חוזרת: "שלח לסניפים נבחרים" וסימון הסניף |
| הלוגו לא מופיע | אין לוגו שמור, או SVG | להעלות PNG/JPG ב-`/dashboard/rentals/labels/settings` |
| ה-cron לא רץ | אין `CRON_SECRET`, הפרויקט לא ב-Vercel, או Cron Jobs כבויים בחבילה | סעיף 4; לבדוק ב-Settings → Cron Jobs |

איפה רואים לוגים: Vercel → Project → **Logs** (לסנן לפי `/dashboard/accounting/mobile` או
`/api/rentals/monthly-reports`). ב-Resend → **Emails** רואים כל מייל שיצא, את הסטטוס שלו
(Delivered / Bounced / Complained) ואת תשובת שרת היעד.

## 8. אבטחה — מה לא לעשות

- לא להכניס את `RESEND_API_KEY` לקוד או ל-git. רק כמשתנה סביבה.
- לא לתת ל-API Key הרשאת Full access — Sending access מספיק.
- `CRON_SECRET` הוא מה שמונע מכל אחד באינטרנט להפעיל שליחה לכל השותפים. אם הוא דלף — להחליף.
- כל כפתורי השליחה במסך מוגנים ב-`requireOwner()` בצד השרת; אין צורך לשנות שום הרשאה.

## 9. אם בכל זאת צריך לגעת בקוד

לא אמור להיות צורך. אבל אם מחליפים ספק מייל (למשל SMTP של Google Workspace במקום Resend), השינוי
כולו בפונקציה אחת: `sendHtmlEmail` ב-`apps/web/lib/mailer.ts`. היא מקבלת `to`, `subject`, `html`
ו-`inlineImages` (הלוגו, שמוצג ב-HTML כ-`src="cid:<contentId>"`), ומחזירה `{ ok, message }`
בעברית. כל שאר המערכת — הדו"ח, התצוגה המקדימה, הבחירה, הסימון "נשלח" וה-cron — לא תלויה בספק.

פקודות לבדיקה מקומית:
```bash
pnpm install
cp apps/web/.env.example apps/web/.env.local   # למלא Firebase + RESEND_API_KEY + REPORT_FROM_EMAIL
pnpm dev
pnpm typecheck
```
